# Restaurant data and image sources

The current seed contains **59 real restaurants in the same 42 provinces**, each with a different photograph matched to that restaurant, its food, view, or premises. The first import replaced 25 fictional demonstration rows with 20 real businesses; the next import added ten businesses in ten previously empty provinces, and the 2026-11-13 import adds another 23 in 23 further provinces. The public Go API contract is unchanged. No external ratings/reviews are imported.

Original snapshot retrieved: **2026-11-12 (Asia/Bangkok)**; the 23-province expansion was researched on **2026-11-13 (Asia/Bangkok)** against the same TAT snapshot.

## Restaurant facts

- **31 records:** [TAT restaurant1 catalogue](https://data.go.th/th/dataset/restaurant1), published by the Tourism Authority of Thailand, via [the downloadable JSON resource](https://datacatalog.tat.or.th/dataset/6d8193a1-7187-4625-a22d-504ab69b427d/resource/53af01a0-9ef5-459a-88c1-befe4690b1f2/download/restaurant.json). The catalogue declares `Open Data Common` and unrestricted public access; it does not provide a more specific license URI. Only factual place fields are normalized here; original marketing descriptions are not copied.
- The downloaded snapshot contains **13,035 source records**, not 13,035 unique verified businesses. This seed is a curated subset with matched, licensed photographs; it does not bulk-import entries with no image or uncertain identity.
- Full source file SHA-256: `c015a3dbac7852b1d6e133d239957a6cbf07bf3c309cc677239d47c685556760` (20,412,327 bytes). The 20 MB raw snapshot is not committed.
- **1 record (Breezeo):** factual name/cuisine/location from its [operator's official page](https://www.royalcliff.com/restaurant/breezeo/); street address from the [Royal Cliff factsheet](https://www.royalcliff.com/wp-content/uploads/2026/01/OnlineRCHG-Factsheet-CN-2026-01.pdf). Its short Thai description is written for this project.

Additional factual sources:

- Other government records: the Department of Industrial Promotion / IPC10 [local products register](https://ipc10.dip.go.th/uploadcontent/IPC10/Purchase%20NEW/ipc10_2564.pdf) for ขนมจีบสังขยาป้าพิณ; the Ministry of Tourism and Sports [Thailand Tourism Directory entry 84040](https://www.thailandtourismdirectory.go.th/restaurants/84040) for ก๋วยเตี๋ยวปากหม้อ พนมสารคาม บางปะอิน; and the Pathum Thani Provincial Public Relations Office [Chai Thung article](https://pathumthani.prd.go.th/th/content/category/detail/id/33/iid/339375). Pa Pin's identity and location are also corroborated by [Suan Dusit University's culinary article](https://food.dusit.ac.th/home/?p=21039). These are short normalized facts, not copied promotional descriptions.
- The original three Commons place records: ร้านอาหารถ้ำกระแซ, Café Amazon พลายชุมพล and Café Amazon สตาร์พลาซ่า อรัญประเทศ. Their file descriptions, visible signs and locality categories identify the photographed business and location. These entries use the Commons file URL as their factual source identity; they are not represented as TAT records.

TAT field mapping: `PLACE_NAME_TH` → name; `PROVINCE_NAME_TH` → province lookup; `PLACE_ADDRESS`, `PLACE_ALLEY`, subdistrict/district/province and postcode → address; `PLACE_LOCATION` → latitude/longitude when present. The seven app categories are curated from food-type labels and the named restaurant's documented cuisine. Empty address components and absent coordinates remain absent; camera GPS is not substituted for a restaurant's coordinates. The source dataset does not include image fields.

`source_url` uses the original JSON resource URL plus `#PLACE_ID=...` as a stable per-record identity; the fragment identifies a row in that downloaded dataset, not an official restaurant detail page. Source IDs and the normalized records are represented directly in `seed.sql`. Do not change the source identity when refreshing an existing business.

These are source snapshots of real businesses, not a guarantee of current operating hours or opening status. Historical awards, stars, external ratings and external reviews are deliberately omitted. Some TAT rows lack street or coordinate details; those have not been invented.

## Photographs and visible attribution

Every image is an actual photograph from Wikimedia Commons, matched by name, branch/province and file description/category. They are not AI-generated pictures, random stock dishes or Google photos. Each file has its own license; the TAT dataset license is not treated as a photo license. Images are remotely served as Wikimedia thumbnails, without tracking query parameters; this project does not claim authorship. Display scaling/cropping is identified as a thumbnail in the credit. Original/file/license links and author names are recorded below.

The existing FE renders `description` on restaurant details. The seed includes a visible `ที่มาข้อมูล:` paragraph and `ภาพ:` credit containing file title, author, license, license URL and Commons file URL, so attribution is available without adding fields to `API_CONTRACT.md`. Preserve this credit when editing a restaurant. The FE uses `imageUrl` directly and retains its SVG fallback for genuine loading failures.

## Import and preservation

Use the existing `go run . seed` command with the intended ThaiFood `DATABASE_URL` exported. The app does not load `.env` automatically. The SQL is embedded at build time, so use a build from this revision; the previously deployed binary embeds the old fictional seed. Running this command changes database content immediately; it does not require an API deployment.

The SQL keeps 77 provinces and 7 categories, deduplicates restaurants by their stable source identity, and leaves later admin edits untouched on replay (`ON CONFLICT DO NOTHING`). It removes only rows with BOTH the exact old fictional `source_name` and fictional URN prefix, only when `updated_at = created_at` (never edited), and only when neither a review nor a favorite references them. Review/favorite writes are briefly locked during that reference check to prevent a concurrent cascade. All other restaurants and all members/reviews/favorites are preserved. A referenced or admin-edited fictional row is retained and needs an explicit later moderation decision; it must never be silently relabeled as a real business.

For the first replacement import, save a permission-restricted backup of the original fictional restaurant rows and record aggregate member/review/favorite counts. Verify list/detail/filter output, all image URLs, replay idempotency and unchanged user data afterward. Do not commit database credentials, backups with user data, or private environment files.

The additive ten-province live import executes only the marked `additional_places` INSERT block from `seed.sql`, after backing up the existing restaurant rows and confirming the target provinces are empty. It does not execute the earlier fictional-row retirement block. Validate the original twenty rows field-for-field, unchanged member/review/favorite counts, thirty rows across nineteen provinces, and identical restaurant IDs/fields after replay. ## Other user-supplied sources

- [Google Places policies](https://developers.google.com/maps/documentation/places/web-service/policies) restrict bulk storage of Places content and require applicable attributions. Google content is not imported into this persistent seed.
- [Foursquare Place Search](https://docs.foursquare.com/fsq-developers-places/reference/place-search) is an API integration rather than an anonymous downloadable dataset; no Foursquare key was supplied or used.
- [Thailand Tourism Directory Open API](https://www.thailandtourismdirectory.go.th/openapi) presents an access-request form. No registration or token request was submitted on the user's behalf.
- [OpenStreetMap/Overpass](https://overpass-turbo.eu/) was assessed, but the public query timed out and is not a dependency of this import. No OSM-derived restaurant records are included, so no ODbL database is mixed into the TAT subset.

Image URLs depend on an external image host. Recheck status/content type and the corresponding file/license when updating the source snapshot; never substitute an unrelated photograph merely to avoid a missing image.
